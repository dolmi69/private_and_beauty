# «Эвервелл» — русская версия сайта клиники

Самостоятельная копия прототипа на Django 6.1.1 и SQLite. Есть публичные страницы, чат, регистрация пациентов, запись на свободное время, кабинет врача и панель менеджера.

## Аккаунты и расписание

Пациент регистрируется на `/register/` и входит на `/login/`. Только пациент может записаться; имя и телефон берутся из его аккаунта. В `/cabinet/` он видит свои записи и может отменить заявку до подтверждения. Слоты на ближайший 21 день создаются командой `python manage.py seed_slots`; её можно запускать повторно. В чате форма записи показывает только свободные часы выбранного врача. Одно время не может быть занято дважды.

Менеджер входит в локальную админку `/manager/dashboard/`, видит все заявки, подтверждает/отменяет их и управляет часами в разделе «Время приёма». На `/manager/team/` он создаёт логин и временный пароль для врача, привязанный к его анкете. Врач входит через `/login/`; в `/cabinet/` видит только свои будущие приёмы, свободное время и загрузку на неделю. Публичная регистрация не даёт выбрать роль врача или менеджера.

Старые заявки сохранены без привязки к аккаунтам пациентов и по-прежнему видны менеджеру. Созданный ранее локальный аккаунт `admin` остаётся менеджером. Для реального использования смените временный пароль `admin`.

Английский проект находится в родительской папке и работает на **порту 8000**. Русская копия находится в `everwell-ru` и работает на **порту 8001**. У версий отдельные базы данных и cookie: их можно открывать одновременно. Английская версия сохранена в `everwell-clinic-en.zip` вместе со снимком её базы.

## Запуск в текущей рабочей папке

В PowerShell, находясь в `everwell-ru`, используйте установленное окружение родительского проекта:

```powershell
..\.venv\Scripts\python.exe manage.py migrate
..\.venv\Scripts\python.exe manage.py seed_slots
..\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

Откройте [русский сайт](http://127.0.0.1:8001/) или [кабинет администратора](http://127.0.0.1:8001/manager/dashboard/). Для остановки сервера нажмите Ctrl+C.

## Установка из отдельного архива

Нужен Python 3.12 или новее. Пример для Python 3.13 и Windows PowerShell; выполняйте команды в папке с `manage.py`:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe manage.py makemigrations clinic
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_slots
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

Миграции включены, поэтому `makemigrations` обычно сообщает об отсутствии изменений. Активация окружения не обязательна. Не перезаписывайте `.env`, если уже внесли свои настройки.

Для macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_slots
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8001
```

## Врачи и запись

`migrate` добавляет шесть вымышленных врачей: терапевта, кардиолога, педиатра, стоматолога, дерматолога и невролога. Повторный запуск не дублирует записи. Восстановить отсутствующие демонстрационные анкеты можно командой `python manage.py seed_doctors`.

Новая заявка всегда получает статус **«Ожидает подтверждения»**. Менеджер меняет статус на **«Подтверждена»** или **«Отменена»**. Время показывается в часовом поясе клиники: по умолчанию `Europe/Moscow`, настройка `CLINIC_TIME_ZONE`.

## Кабинет администратора

На главной странице есть кнопка «Вход для администратора». Она открывает форму входа по логину и паролю, а после авторизации — список всех заявок. Для записи пациент регистрируется; доступ к чужим заявкам и админке запрещён.

Для администратора регистратуры с ограниченными правами:

```bash
python manage.py create_manager reception
```

В текущей общей рабочей папке вместо `python` можно использовать `..\.venv\Scripts\python.exe`. Команда запросит пароль дважды. Сотрудник получит права просмотра врачей и просмотра/изменения заявок. Он не сможет управлять пользователями, удалять заявки или редактировать анкеты врачей.

Вход: `/manager/dashboard/` или `/admin/`. Доступны поиск по имени, телефону и врачу, фильтры по статусу, врачу и дате. После изменения статуса в списке нажмите «Сохранить».

В русской копии отдельная база: учётные записи английской версии не переносятся автоматически. Готовых паролей в коде нет. Полный доступ можно получить, создав своего суперпользователя командой `createsuperuser`.

## Русский чат и ГигаЧат

Без ключей чат сразу работает в локальном деморежиме:

```text
Посетитель: У меня болит зуб.
Администратор: Как давно это вас беспокоит? Приём нужен взрослому или ребёнку?
Посетитель: Два дня. Я взрослый.
Администратор: Можно начать с консультации: Михаил Орлов, стоматолог…
```

Кнопка «Оставить заявку» открывает форму с выбранным врачом. Кнопка на карточке врача выполняет то же действие. Для нового сценария нажмите значок сброса диалога.

Промпт в `clinic/services.py` запрещает ставить диагнозы, предлагать лекарства и назначать лечение. Модель возвращает идентификатор врача, ключ уточняющего вопроса и признак возможной экстренной ситуации. Сервер проверяет ответ и формирует русское сообщение из разрешённых формулировок. Произвольный текст модели посетителю не показывается.

Для подключения API заполните `.env`:

```dotenv
GIGACHAT_CREDENTIALS=ваш_ключ_авторизации
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_BASE_URL=https://api.giga.chat/v1
CHAT_FORCE_MOCK=false
```

Используйте ключ авторизации проекта в Base64 без префикса `Basic`, а не временный токен. Значение `GIGACHAT_SCOPE` должно соответствовать аккаунту. Имена переменных, модели, JSON-полей и URL остаются в формате API.

При необходимости укажите доверенный PEM-набор сертификатов в `GIGACHAT_CA_BUNDLE`. Проверка TLS включена. После изменения `.env` перезапустите сервер.

Реализованы OAuth с уникальным `RqUID`, кеширование токена, ограничения времени запроса и переход к локальному подбору при ошибке API. Документация: [авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api), [генерация ответа](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat), [сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates).

## Проверки

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
```

Проверяются страницы, создание врачей, заявки, часовой пояс, статусы, права, CSRF, неверный JSON, история чата, ограничения частоты запросов, OAuth и обработка ответа модели. HTTP-вызовы ГигаЧата в тестах имитируются; реальный сервис требует вашего ключа.

## Особенности прототипа

- Заявка резервирует выбранный слот. Рассылка SMS/писем не реализована: менеджер подтверждает приёмы вручную.
- Имя, телефон и время хранятся в SQLite. Поля формы не отправляются в ГигаЧат. При включённом API ему передаётся текущая переписка; об этом сообщает чат.
- История ограничена 12 сообщениями и хранится в серверной сессии со сроком действия 30 минут. Сброс очищает текущий диалог. Просроченные сессии удаляются командой `python manage.py clearsessions`.
- Врачи, контакты, часы работы и услуги вымышлены. Локальный подбор по ключевым словам демонстрирует работу приложения и не заменяет медицинскую оценку.
- Для публикации потребуются реальные настройки, секретный `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=false`, разрешённые домены, HTTPS и сервер WSGI/ASGI. Встроенный `runserver` предназначен для разработки. Для нескольких процессов нужен общий кеш.

Для изменения дизайна откройте `clinic/templates/clinic/base.html`, для логики чата — `clinic/services.py`, для полей записи — `clinic/models.py` и `clinic/forms.py`.
